# 提示词片段管理与批量替换设计

## 1. 目标

在现有 Git 配置管理能力上增加“提示词片段库”，让管理员可以维护可复用的完整 XML 片段，并按照目标环境和路径 glob 条件，将选定片段一次性替换到多个提示词配置文件中。

批量操作必须先预览、后确认；所有目标文件使用一个 Git commit 提交。任何目标文件存在结构异常、远程版本变化或校验失败时，整批操作不得提交。

## 2. 已确认的业务规则

- 提示词配置中的 XML 标签是原样的多行文本，不是 JSON 字符串中的转义文本。
- 替换整个 XML 元素，包括开始标签、属性、内部内容和结束标签。
- 一个片段文件只包含一个完整 XML 根元素。
- 片段文件路径是片段的唯一标识；文件名可以自定义。
- 多个片段文件可以使用相同根标签，以支持同一标签的多个并行版本。
- 批量操作从一个明确选中的片段文件发起，以该文件根标签定位目标内容。
- 目标文件中没有该标签时记为“未命中”，不修改文件。
- 目标文件中同名标签出现多次、嵌套出现、开始/结束标签不完整或结构无法确定时，记为异常并阻止整批提交。
- 批量替换仅管理员可执行，片段库仅管理员可编辑。
- 只有已经提交到当前远程分支的片段版本可以用于批量替换。

## 3. 环境模型

环境增加 `kind` 字段：

- `config`：普通配置环境，是批量替换的目标。
- `fragment-library`：提示词片段库，是批量替换的来源。

旧配置没有 `kind` 时按 `config` 处理，以保持兼容。功能根据 `kind` 判断，不依赖“prompt 模板”等固定名称或环境 ID。可以配置多个片段库。

片段库支持管理员新建、重命名、删除和普通编辑片段文件。新建文件时输入相对路径和根标签名，系统生成可编辑的 XML 骨架并立即提交。重命名和删除也各自形成一个 Git commit。

## 4. 路径匹配

路径模式相对于每个所选目标环境的根目录计算，开头 `/` 可省略且不代表服务器绝对路径。

- `*`：匹配一层路径内的任意字符，不跨 `/`。
- `?`：匹配一层路径内的单个字符。
- `**`：匹配任意层级目录。
- `/tob-uat/*_prompt_cn`：匹配 `tob-uat` 的直属文件。
- `/tob-uat/**/*_prompt_cn`：同时匹配任意深度子目录。
- 路径统一使用 `/`，禁止 `..`，并按 Linux 规则区分大小写。

目标环境可多选。相同模式分别相对于每个环境根目录执行。片段库不能作为目标环境。

## 5. XML 片段识别

不得使用跨行正则直接匹配完整元素。服务端使用逐字符的标签扫描器，识别引号、注释、CDATA、处理指令、开始标签、结束标签和自闭合标签，并按标签名跟踪嵌套深度。

片段保存时校验：

- 文件除首尾空白外只有一个根元素；
- 根标签名合法；
- 开始和结束标签配对且嵌套正确；
- 不限制根标签名与其他片段重复。

目标文件扫描时，选中片段的根标签必须恰好出现一次。替换保持目标元素前后的原始文本不变。

## 6. 批量预览

预览请求包含：

- 来源片段文件路径；
- 目标环境 ID 列表；
- 路径 glob。

服务端先拉取远程分支，并只读取远程 HEAD 中已提交的来源片段和目标文件。预览返回：

- 预览基准远程 HEAD；
- 来源片段路径、blob、根标签名和完整内容；
- 匹配文件总数；
- 可变更、内容相同、未命中和异常文件数量；
- 每个文件的环境、相对路径、状态、原因、替换前和替换后内容。

存在任何异常文件时 `canApply=false`。可变更文件默认勾选，管理员可以取消部分正常文件；异常文件不能通过取消勾选绕过整批阻断。

## 7. 批量提交与一致性

确认请求携带预览基准 HEAD、相同的来源和筛选条件，以及用户最终选择的文件列表。

服务端在进程级 Git 互斥区内执行：

1. 再次拉取远程分支。
2. 验证远程 HEAD 与预览基准一致；不一致时返回冲突并要求重新预览。
3. 重新计算完整预览，防止客户端篡改路径或结果。
4. 确认没有异常，且选择的文件都是本次预览中的可变更文件。
5. 要求所有目标文件没有未提交修改，避免覆盖待替换内容；其他文件的草稿不受影响。
6. 校验所有替换后文件的既有 JSON/YAML 格式。
7. 写入并暂存全部目标文件。
8. 使用一个 commit 提交全部目标文件并推送。
9. 推送或提交失败时，恢复到操作前的干净状态。

提交信息记录来源片段路径、来源 blob、XML 标签名、目标环境、文件数量和操作人，保证同一标签的不同片段版本可以审计。

## 8. 并发与权限

- 仓库同步、单文件提交、历史恢复、丢弃修改、片段文件管理和批量提交共用同一个进程级互斥队列。
- 批量预览也进入互斥区，保证读取远程引用时不与本进程写操作交错。
- 所有片段管理和批量接口在服务端强制校验管理员身份，不能只依赖前端隐藏按钮。
- 普通配置环境继续沿用原有逐环境编辑权限。

## 9. 前端交互

片段库页面在文件列表上方显示：

- 新建片段；
- 重命名；
- 删除；
- 批量替换。

批量替换对话框包含来源片段、根标签、目标环境多选、路径模式、预览统计、逐文件状态与差异，以及最终提交说明。远程版本变化后清空旧预览并提示重新生成。

## 10. 暂不纳入本期

- 在项目 A 运行时解析 `{{fragment:...}}` 引用。
- 在目标提示词中插入额外标记或版本属性。
- 用关联清单实时展示每个目标文件当前来自哪个片段版本。
- 正则表达式路径匹配和排除模式。

如果后续需要展示“当前片段来源/是否过期”，可以增加不进入提示词正文的关联清单；本期先以 Git 提交元数据完成审计。
